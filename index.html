Ajuda & Documentação — DER / EER Builder

📘 Documentação do Formato JSON — DER / EER Builder
Guia completo da notação JSON para especificação de diagramas Entidade-Relacionamento e Entidade-Relacionamento Estendido (EER).
🧬 1. Especializações EER (Círculos d, o, u)
No EER, os círculos de especialização e categoria utilizam as letras d, o e u:
Símbolo Nome Regra de Negócio Exemplo Prático
d Disjunta Mutuamente Exclusiva. Uma entidade pertence a no máximo uma sub-classe. Funcionario → Mensalista OU Horista
o Sobreposta (Overload) As sub-classes podem se sobrepor. Pode pertencer a múltiplas sub-classes. Pessoa → Aluno E Professor
u União / Categoria A super-classe é uma Categoria composta pela união das sub-classes. Veiculo → Carro e Moto

• Linha Dupla (Totalidade): Configurada por "total": true no nó de especialização.

• Atributo Definidor: Opcional, via "definingAttribute": "TipoContrato".

📌 2. Tipos de Atributos no JSON
Valores aceitos na propriedade "type" de cada atributo:
  • "key": Chave Primária (Sublinhado sólido visual).
  • "partial_key": Chave Parcial / Discriminador (Sublinhado tracejado para entidade fraca).
  • "simple": Atributo Simples regular.
  • "multivalued": Atributo Multivalorado (Elipse Dupla).
  • "derived": Atributo Derivado (Elipse Tracejada).
🔄 3. Relacionamentos & Auto-Relacionamentos Recursivos
Relacionamentos usam a lista de "participants". Para auto-relacionamentos recursivos (ex: Supervisão de Empregados), inclua duas entradas para a mesma entidade com seus respectivos papéis ("role") e cardinalidades: 
{
  "name": "supervisao",
  "type": "recursive",
  "participants": [
    { "entity": "Empregado", "role": "É supervisionado", "cardinality": "1" },
    { "entity": "Empregado", "role": "Supervisiona", "cardinality": "N" }
  ]
}
🚀 4. Exemplo JSON Completo Interativo
Cole este código ou clique no botão abaixo para testar diretamente no editor:
Exemplo EER em JSON 
{
  "entities": [
    {
      "name": "Funcionario",
      "type": "strong",
      "attributes": [
        { "name": "CPF", "type": "key" },
        { "name": "Nome", "type": "simple" },
        { "name": "Telefones", "type": "multivalued" }
      ]
    },
    {
      "name": "Mensalista",
      "type": "strong",
      "attributes": [{ "name": "SalarioMensal", "type": "simple" }]
    },
    {
      "name": "Horista",
      "type": "strong",
      "attributes": [{ "name": "ValorHora", "type": "simple" }]
    }
  ],
  "specializations": [
    {
      "type": "d",
      "superEntity": "Funcionario",
      "subEntities": ["Mensalista", "Horista"],
      "total": false,
      "definingAttribute": "TipoContrato"
    }
  ]
}

📖 Resumo Rápido de Símbolos & Notação Peter Chen
Tabela de consulta rápida de toda a sintaxe suportada pelo parser:
Símbolo / Sintaxe Significado Símbolo / Sintaxe Significado
NomeEntidade { ... } Entidade Forte (Retângulo) entidade fraca Nome { ... } Entidade Fraca (Retângulo Duplo)
*Atributo ou #Atributo Chave Primária (Sublinhado Sólido) _Atributo_ Chave Parcial (Sublinhado Tracejado)
~Atributo Atributo Derivado (Elipse Tracejada) ++Atributo ou Atrib[] Multivalorado (Elipse Dupla)
Nome[Sub1, Sub2] / (Sub1, Sub2) Atributo Composto relacionamento fraco nome(...) Relacionamento Fraco (Losango Duplo)
ObrigNome(...) / obrigatorio ... Participação Total / Obrigatoriedade (Linha Dupla) especializacao d|o (A -> B, C) Especialização EER (Círculo d/o/u)
📌 1. Entidades Fortes e Tipos de Atributos
Define uma entidade regular (retângulo) com seus atributos. Prefixos: * (Chave Primária), ~ (Derivado), ++ (Multivalorado), e Nome[Sub1, Sub2] ou Nome(Sub1, Sub2) para Atributos Compostos.
Exemplo: Entidade Forte e Atributos 
Aluno {
  *CPF,
  Nome[PrimeiroNome, Sobrenome],
  ~Idade,
  ++Telefones
}
⛓ 2. Entidades Fracas e Chaves Parciais
Entidades que dependem de uma entidade identificadora. Retângulo duplo visual. Use _Nome_ (undescores nas pontas) para chave parcial (discriminador).
Exemplo: Entidade Fraca 
entidade fraca Dependente {
  _NomeDependente_,
  Parentesco
}
🔗 3. Relacionamentos, Cardinalidades e Linha Dupla
Associações com cardinalidades (1:1, 1:N, N:N). Use relacionamento fraco para entidades fracas, ou prefixos como Obrig... / obrigatorio ... para Participação Total (Linha Dupla).
Exemplo: Relacionamentos 
pertence (Curso N : 1 Area)
ObrigCompoe (Curso 1 : N Modulo)
relacionamento fraco compoe (Curso 1 : N Modulo)
💎 4. Relacionamentos com Atributos
Em associações N:N, você pode definir atributos próprios do relacionamento dentro de chaves { }.
Exemplo: Atributo no Losango 
matricula (Aluno N : N Curso) {
  DataMatricula,
  Pago
}
🔄 5. Auto-Relacionamentos (Recursivos) e Papéis (Roles)
Quando a mesma entidade se conecta duas vezes ao relacionamento, use [papel] para diferenciar cada ponta.
Exemplo: Auto-Relacionamento 
integra (Area [integrante] N : 1 Area [integrada])
🧬 6. Especialização e Generalização EER
Hierarquias de herança com círculo central (⊂). Tipos: d (Disjunta), o (Sobreposta) ou u (União/Categoria).
Modificadores: total = linha dupla (toda superentidade obriga pertencer a uma subclasse); sem modificador ou parcial = linha simples.
Atributo Definidor: [NomeAtrib] opcional ao final — exibido ao lado da linha superclasse→círculo.
Parcial + Disjunta + Atributo Definidor 
especializacao d (Funcionario -> Mensalista, Horista) [TipoContrato]
Total + Sobreposta (linha dupla) 
especializacao total o (Pessoa -> Aluno, Professor)
Categoria / União (u) 
categoria u (Veiculo -> Carro, Moto)
💬 7. Comentários e Comandos de Console
Linhas com // ou # são comentários. O console aceita comandos incrementais de uma linha.
Exemplo: Comandos de Console 
// Comentário ignorado
criar entidade Departamento
adicionar atributo Email em Aluno
deletar entidade Curso
